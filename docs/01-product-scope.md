# 产品范围与验收标准

## 目标

把官方 DeepSeek Harness Web UI 交付为一个可靠的 macOS 桌面应用。用户无需安装 Node.js、执行命令或手动管理端口；双击应用即可进入 Harness，退出应用即可完整结束由本应用启动的运行时。

本项目的差异化不在重写 Agent，而在稳定交付：固定兼容版本、可诊断启动、macOS 原生生命周期、安全的本地承载以及可验证的签名和更新。

## 目标用户

- 希望使用 DeepSeek Harness，但不希望长期保留终端窗口的 macOS 开发者。
- 需要在多个本地代码仓库中工作、查看任务状态并接收完成通知的用户。
- 接受 Harness 当前仍处于 Developer Preview、但要求桌面发行版自身可回滚和可诊断的用户。

## V1 范围

### 安装与启动

- 首个个人可用版本提供 Apple Silicon arm64 的签名、公证 DMG；同时发布 ZIP。Intel x64 保留为后续可选构建。
- 应用内置与目标架构匹配的 Node.js 运行时和固定版本 `@deepseek-ai/dsh`。
- 首次启动创建独立运行时目录；不读取或修改用户已有的全局 dsh 安装。
- 保证单实例；第二次启动时激活已有窗口。
- 首次自动选择可用回环端口并稳定复用；升级时按旧日志物理顺序迁移上一公开版最后 ready origin，同时要求轮转日志中保留的全部不同 ready 端口先释放。候选 endpoint 必须通过本次启动 secret 的 HMAC challenge；任一遗留端口持续占用都会在复制或打开 Runtime Home 前失败关闭并给出操作提示，再显示 Harness UI。
- 启动失败时显示本地诊断页，提供重试、复制脱敏诊断信息和打开日志目录。

### macOS 体验

- 标准应用菜单：About、Settings、Reload Harness UI、Restart Harness、Open Logs、Quit。
- 点击 Dock 图标能恢复主窗口；关闭窗口只隐藏窗口，显式 Quit 才结束运行时。
- Harness 任务完成或等待用户确认时，在能可靠识别事件后发送系统通知；该能力不阻塞 V1 首发。
- 外部链接交给默认浏览器，Harness UI 不能在主窗口中导航到任意互联网页面。

### 配置与数据

- Harness 配置和会话由 Harness 自己管理，桌面壳不复制 API Key。
- 桌面壳只保存窗口状态、更新偏好、日志级别和上次成功启动信息。
- 清楚展示应用版本、运行时版本、运行时目录和当前端口。
- 用户可导出脱敏诊断包；默认不得包含 API Key、环境变量全集或项目文件内容。
- 允许使用 Harness 官方扩展 seam 显示当前凭据所属账户的官方余额，以及由桌面壳提供只读 Workspace Review；不得显示估算消费，也不得借此增加项目写入能力。

### 更新与恢复

- 应用更新同时更新桌面壳和 Harness 运行时。
- 更新包必须经过代码签名验证；下载完成后由用户选择重启安装。
- 新版本首次启动失败时保留旧用户数据，不执行不可逆迁移。
- 运行时意外退出时最多自动重启两次，之后进入诊断页，避免无限重启。

## 明确不做

- 不重写 Harness UI、Agent loop、工具系统、会话协议或插件协议。
- 不提供云端代理、账号系统、遥测后台或远程访问。
- 不进入 Mac App Store；Harness 需要启动子进程并访问用户选择的开发目录，不适合 MAS App Sandbox。
- 不自动安装社区插件，不默认修改用户项目。
- 不保证兼容任意用户自行替换的 dsh 版本。
- V1 不做多窗口、多运行时实例和移动端远程控制。
- Desktop Companion 不复制 Harness 的 Agent、会话、工具详情或设置 UI；Workspace Review 第一版不保存、删除、撤销、stage 或 commit。

## V1 验收标准

1. 在干净的 macOS 14+ Apple Silicon 环境中，无全局 Node/dsh 也能安装并启动。
2. 首次启动到 Harness UI 可交互的 P95 小于 8 秒（不含首次网络模型请求）。
3. 持久端口短暂被 orphan Runtime 占用时等待其退出；持续占用时给出可操作故障，且绝不连接或按名称终止占用该端口的未知进程。
4. 主窗口只能加载本应用启动并验证过的回环 origin。
5. Quit 后 3 秒内结束本应用启动的 Harness 进程及其子进程；不得结束其他 dsh/node 进程。
6. Harness 崩溃、运行时缺失、端口失败和 UI 就绪超时均呈现可操作的错误信息。
7. `codesign`、Gatekeeper、notarization ticket 和 arm64 冒烟测试全部通过。
8. 从上一个公开版本升级后，会话与 Harness 配置仍可读取；失败时数据保持原样。

## 后续候选范围

- 根据 Harness 的稳定事件接口增加任务完成、审批等待通知。
- 菜单栏常驻模式和启动时自动运行。
- 经过兼容性检查的高级“切换运行时版本”功能。
- 面向桌面能力的官方 dsh 插件，而不是向 Harness 页面注入不稳定 DOM 脚本。
