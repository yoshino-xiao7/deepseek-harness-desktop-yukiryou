## 简体中文

这是一次 Harness Runtime 升级 Beta，将内置 DeepSeek Harness 更新至 `0.1.0-rc.8`。

### 更新内容

- 获得 rc.8 的原生多模态请求、`/goal` 与 `/plan` 图文输入、文件/会话引用、可安装 Profile Bundle 子代理及多项稳定性改进。
- 针对 rc.8 将核心 peer 组合与 React 版本显式锁定，保持离线安装和跨机器构建可复现；原生 PTY、sharp 与 koffi 验证继续通过。
- 首次使用 rc.8 启动前，如果 Runtime Home 非空，会在同级目录保留 `runtime.pre-dsh-0.1.0-rc.8` 完整副本（若同名路径已存在则使用编号后缀），再允许 Harness 打开不兼容的新存储格式。
- 自定义模型“自动继承 / 仅文本 / 文本与图片”控件继续保留。经官方包核对，rc.8 新增的是 `deepseek-official` adapter 的 `inputModalities`，尚未覆盖自定义 Provider 的 `models[].input` 设置 UI。
- 适配 rc.8 本地 Web Profile 默认打开浏览器的新行为；从桌面应用启动时，Harness UI 只在应用窗口内显示。
- 修复安装包启动页品牌图路径；开发环境与打包应用现在使用同一份 Vite public asset。
- 修复本版安装后完全退出应用或手动重启 Harness 时落入空会话的问题。桌面壳会稳定复用本机 Harness origin；从正常退出且保留 ready 日志的上一公开版升级时，也会迁移最后使用的 origin，让 rc.8 原生 `dsh.sessions.current` 继续恢复最后活跃会话。升级门禁会创建真实非空 Session，验证 current selection 和 Session 集合不变且不新增空白 Session。
- 稳定端口新增每次启动 secret 的 HMAC 持有证明；端口被其他本机服务占用时不会加载伪造页面。一次性旧日志迁移还要求轮转日志中保留的全部不同 ready 端口先释放，任一遗留 Runtime 仍占用端口都会在复制或打开 Runtime Home 前失败关闭。

### 后续开发方向

- 本版同时接受新的长期架构决定：产品 UI 优先使用 Harness 正式插件 seam，Electron 双/单 webContents 切换收敛到 main 层 DesktopProductCarrier，根布局 composition 则只存在于 Runtime 的 DesktopFramePlugin。
- Windows 11 x64 与插件市场已进入后续规划，但本安装包仍只支持 Apple Silicon macOS，不包含尚未完成的市场或 Windows 能力。

## English

This beta upgrades the bundled DeepSeek Harness runtime to `0.1.0-rc.8`.

### What’s new

- Adds rc.8 native multimodal requests, image input for `/goal` and `/plan`, file/session references, installable Profile Bundle subagents, and upstream stability improvements.
- Pins the rc.8 peer composition and React versions explicitly for reproducible offline builds; native PTY, sharp, and koffi probes continue to pass.
- Before rc.8 first opens a non-empty Runtime Home, the app preserves a complete sibling copy at `runtime.pre-dsh-0.1.0-rc.8` (or a numbered suffix if that path already exists) because the new storage format is incompatible.
- Keeps the custom-model “inherit / text / text and images” control. Package inspection confirmed that rc.8 adds `inputModalities` to the `deepseek-official` adapter but still does not expose custom-provider `models[].input` in the settings UI.
- Adapts to rc.8 opening its local Web Profile in the default browser; desktop launches now keep the Harness UI inside the app window.
- Fixes the packaged loading-page brand image path so development and installed builds use the same Vite public asset.
- Fixes restarts of this build falling into an empty session. The desktop shell now reuses a stable local Harness origin. A normally closed previous public release with its ready log retained is also migrated so rc.8 can restore its native `dsh.sessions.current` selection. The upgrade gate creates a real nonblank Session and verifies that current selection and the exact Session set remain unchanged with no blank Session added.
- Adds a per-start HMAC secret-possession proof for the stable port, so a conflicting local service is never loaded as trusted Harness content. During one-time legacy-log migration, every distinct ready port retained across rotated logs must first become free; any surviving Runtime fails closed before Runtime Home is copied or opened.

### Future direction

- This release also accepts the long-term architecture decision: product UI is Plugin-first on official Harness seams, Electron carrier switching stays in a main-process DesktopProductCarrier, and root composition stays in the Runtime DesktopFramePlugin.
- Windows 11 x64 and the plugin marketplace are now planned work, but this installer remains Apple Silicon macOS-only and does not include either unfinished capability.
