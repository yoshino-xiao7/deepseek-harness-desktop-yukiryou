# 1.0.9 实施与验证记录

日期：2026-09-05。开发分支：`yukiryou/v1.0.9`，从已发布的 `origin/main`（`6e82e85` / `v1.0.8`）建立。对应计划：[更新体验、外部插件更新与启动恢复](14-update-experience-and-plugin-recovery-plan.md)。

## 已实现

- 无更新或首次检查时不显示更新按钮，设置保持原宽；确认更新后以 420ms 顺序动画先让位、后显现。同一当前版本与目标版本组合通过内存及本地存储记录，进度变化、下载完成和重挂载不重播；减少动态效果时直接显示。
- 更新按钮使用 `sidebar.footer.action`，移除 preload 固定定位及其 DOM/尺寸观察器。下载中保留键盘焦点和状态提示、阻止重复命令；设置与更新分别获得 hover/active/focus 反馈。rc.1 同排几何通过精确版本选择器兼容，删除条件见临时补丁登记。
- 外部插件的更新检查结果可见；列表补全未挂载的外部安装，避免停用后消失。外部详情使用自身经过核实的身份，不再被发现目录中的不可安装条目覆盖。展示接管更新说明；本地/开发/未核实依赖来源不会自动替换成同名 Registry 包。
- 更新停用插件时保留启用偏好，试运行不加载该插件；接管前将外部启用状态传入受管事务。原有精确版本、预览凭据、安装/回退事务继续生效。
- 新增宿主持久化启动记录、隔离配置和安全启动。Loader 错误中的 entry ID 与已安装包身份共同匹配时隔离整个插件；无法定位或精准隔离后仍失败，则启动仅包含内置 bundle 的独立配置。
- 安全启动不解析用户 bundle、profile 补丁或 home 补丁，原 `DSH_HOME` 保持不变。恢复记录损坏时保留损坏文件并进入安全模式，不能重置为无约束正常启动。
- 事务恢复/精准隔离与安全回退共用持久化预算；自动恢复最多追加两次。隔离列表保留至用户试启用，逐个恢复失败不清除其他隔离项。
- 独立故障页提供安全启动；安全启动仍失败时明确告知已停止自动重试。恢复成功有原生提示；应用菜单提供恢复管理，市场清单标识恢复模式跳过的插件。
- 保留 Forge Vite 插件原有打包过滤策略，仅打包 `.vite` 产物；Runtime 沿用 `extraResource`，不新增自定义过滤覆盖。

## 实现边界与评审重点

1. 错误归因依赖固定 Runtime 的 Loader 标签加本机身份匹配。网络错误、普通包名文本或无法核实身份的错误不会被当成某插件的确定故障。依赖冲突无法定位时使用安全模式，保留“原因未确定”的结论。
2. 安全模式跳过全部用户扩展及用户补丁，第三方模型和部分偏好可能不可用；不宣称业务功能全部恢复。市场变更需要正常配置试运行才可提交，更新确认明确说明恢复模式中的正常配置试运行。
3. 同一进程权限下的插件并非安全沙箱。此机制针对故障恢复，不抵御恶意插件伪造日志或主动篡改磁盘状态。
4. 配置和代码回退不等于插件私有数据迁移回退。带不可逆数据迁移的插件不能据此宣称无损回退。
5. 持久化健康标记要求 Runtime 认证就绪、页面导航完成及受管事务提交；页面能否完整交互仍以桌面 E2E 和人工验收为准。
6. 未改变 Runtime 版本（仍为 `0.1.2-rc.1`）。未操作日常用户 profile、未推送、未合并 main、未创建发行 tag。
